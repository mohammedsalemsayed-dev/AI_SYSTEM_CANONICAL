# Milestone H — Tauri Packaging Plan


---

## 1. Purpose

Milestone H ships a working shell as a loopback HTTP + SSE server plus a no-build web page.
This step turns that into a **double-clickable native app**: a Tauri v2 Rust shell that

- **spawns the Python server as a sidecar** — `nexus-server`, a PyInstaller one-file build
  of `app/ui/sidecar_main.py` — on startup, with a per-user data dir;
- **waits for readiness** (TCP connect to the loopback port) then points the WebView at
  `http://127.0.0.1:<port>`, so the frontend and API are unchanged;
- **manages the lifecycle** — kills the sidecar on window close / app exit;
- **bundles** to `.msi` / NSIS (Windows), `.dmg` (macOS), `.deb` / AppImage (Linux).

Guiding rules:
- **§15.2 driver architecture** — the app owns the shell and the control plane (Python); it
  *drives* the OS WebView through Tauri. No control-plane logic moves into Rust; `main.rs` is
  process supervision + one navigate call.
- **No behaviour change** — the sidecar is the same `app.ui.server` the CLI runs. The WebView
  loads the same page from the same API. Packaging adds a window and a lifecycle, nothing
  else.
- **Read-only by default** — the sidecar starts without `--allow-submit`; task submission
  from the packaged app is a later, explicit opt-in (a settings toggle), not on by default.
- **Honest boundary** — a real binary needs a Rust toolchain + platform build tools +
  PyInstaller, none of which are in this build environment. This step delivers the complete,
  correct scaffold and a one-command build script; producing the binary is `install
  prerequisites → run the script`, exactly like the un-run live harnesses in earlier
  milestones.

## 2. In scope

| Concern | Implementation |
|---|---|
| Sidecar entrypoint | `app/ui/sidecar_main.py` — frozen-friendly: default DB under the OS app-data dir, port from `NEXUS_PORT` / `--port`, submit **off** unless `NEXUS_ALLOW_SUBMIT=1`, resolves `web/` under `sys._MEIPASS` when frozen. |
| Path resolution | `app/ui/paths.py` — `web_dir()` returns the frontend dir whether running from source or a PyInstaller bundle; `default_db_path()` returns the per-user event-log path. `server.py` uses `web_dir()`. |
| Sidecar build | `desktop/build_sidecar.py` — runs PyInstaller (`--onefile`, `--name nexus-server`, `--add-data app/ui/web`, `--collect-submodules app`) and copies the artifact to `desktop/src-tauri/binaries/nexus-server-<target-triple>[.exe]` (Tauri sidecar naming). |
| Tauri project | `desktop/src-tauri/`: `Cargo.toml` (tauri v2 + tauri-plugin-shell + serde_json), `tauri.conf.json` (identifier, window, `bundle.externalBin`, bundle targets, CSP), `build.rs`, `capabilities/default.json` (shell-execute scope for the sidecar), `src/main.rs`. |
| Rust shell | `src/main.rs` — `setup()`: resolve app-data dir, spawn `nexus-server` sidecar with `--db` / `--port`, drain its stdout to the Tauri log, TCP-poll the port (~20 s budget), build the `main` WebviewWindow at the localhost URL (or a bundled `splash.html` on timeout). `run()` handler: on `ExitRequested`, `child.kill()`. |
| Frontend dist | `desktop/dist/splash.html` — a minimal "starting NEXUS…" page used as `frontendDist` and shown until/if the sidecar is up. The real UI is served by the sidecar. |
| Icons | `desktop/gen_icons.py` (Pillow) writes `desktop/app-icon.png` (1024²) and the Tauri set (`32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.ico`); `.icns` is generated by `npm run tauri icon` on macOS. PNGs committed. |
| One-command build | `desktop/build.py` — `build_sidecar.py` then `npm ci` then `npm run tauri build`; prints the bundle path. Fails with a clear message if `cargo` / `npm` / `pyinstaller` is missing. |
| Docs | `desktop/README.md` — prerequisites per OS, the build recipe, the dev loop (`npm run tauri dev`), and the "not buildable in this environment" note. |

## 3. Out of scope (deferred)

| Deferred | Why |
|---|---|
| Actually producing signed installers here | no Rust toolchain / code-signing certs in this environment |
| Auto-update (Tauri updater + a release feed) | needs a hosting endpoint + signing keys; a later ops task |
| Bundling a portable CPython instead of PyInstaller | heavier; PyInstaller one-file is sufficient and standard |
| Tray icon, global shortcuts, deep links | additive Tauri plugins; not needed for the first packaged build |
| In-app settings UI (port, submit toggle, data dir) | the sidecar already honours env / flags; a settings panel is a frontend follow-up |

## 6. Acceptance criteria

Gate order: UNIT → INTEGRATION → FAILURE → SECURITY → RECOVERY → BUILD.

- **Unit** — `web_dir()` returns an existing directory containing `index.html` from source;
  `default_db_path()` is under the per-user data dir and its parent is creatable;
  `tauri.conf.json` and `capabilities/default.json` parse as JSON and contain the identifier,
  the window label `main`, `bundle.externalBin` naming `nexus-server`, and a shell-execute
  scope entry for it.
- **Integration** — `sidecar_main` started in-process (or as a subprocess on an ephemeral
  port) serves `GET /api/health` 200 and `GET /` HTML; `POST /api/tasks` returns 405 unless
  `NEXUS_ALLOW_SUBMIT=1`.
- **Failure** — `build.py` exits non-zero with a named missing prerequisite when `cargo` /
  `npm` / `pyinstaller` is absent (the state in this environment) — verified here.
- **Security** — the sidecar binds loopback only (inherited from `server.py`); the capability
  file grants shell-execute **only** to the `nexus-server` sidecar, nothing else; submit
  stays off by default.
- **Recovery** — killing the sidecar and restarting it against the same data dir renders the
  prior event log (inherited from H); `main.rs` re-spawns cleanly on app relaunch.
- **Build** — on a machine with Rust + platform build tools + PyInstaller, `python
  desktop/build.py` produces a bundle; **not run here** (no Rust toolchain).

## 7. Tunable starting values

- Sidecar port: **8770** (matches the CLI default; overridable via `NEXUS_PORT`).
- Readiness poll: TCP connect every **300 ms**, up to **60** tries (~18 s), then fall back to
  `splash.html`.
- Window: **1280×820**, resizable, title `NEXUS`.
- Bundle identifier: `com.nexus.controlplane` (placeholder; set before any real release).

## 8. Risks

- **Rust side is not compile-verified here** — `main.rs` / `Cargo.toml` / the capability file
  are written to the Tauri v2 API but cannot be `cargo build`-checked in this environment.
  The Python side (sidecar, paths, config parsing) *is* tested. The README flags this and
  pins the Tauri v2 line so the API surface is stable.
- **PyInstaller one-file startup latency** — first launch unpacks to a temp dir; the
  readiness poll budget (~18 s) covers a cold start on a slow disk. If it still times out the
  window shows `splash.html` and the user can retry; it is not a crash.
- **Sidecar port already in use** — the shell does not currently probe for a free port; a
  second instance would collide. Acceptable for a single-user desktop app; a
  pick-a-free-port handshake is a follow-up.
- **Capability-scope drift** — the exact `shell:allow-execute` scope shape has shifted across
  `tauri-plugin-shell` point releases; the README calls out verifying it against the
  installed plugin version.
- **Code signing** — unsigned bundles trip SmartScreen / Gatekeeper. Signing is deferred
  (needs certs); documented.
